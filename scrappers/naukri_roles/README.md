# naukri_roles — clinical-research & pharma-regulatory jobs from naukri.com

Scrapes healthcare job listings from [naukri.com](https://www.naukri.com/),
India's largest job board, and emits both a rich per-source CSV and the shared
HealthCareers.club 22-column import file.

## Data source

naukri.com is a client-rendered Next.js SPA backed by a private JSON API:

```
GET https://www.naukri.com/jobapi/v3/search
    ?noOfResults=20&urlType=search_by_keyword&searchType=adv
    &keyword=<role family term>&pageNo=<N>&sort=f
    &seoKey=<role-family-term>-jobs[-N]
-> { "noOfJobs": 41073, "jobDetails": [ {card}, ... ], "clusters": {...} }
```

The listing is filtered **at the source** to the *Healthcare & Life Sciences*
functional area — the [`/healthcare-and-life-sciences-jobs`](https://www.naukri.com/healthcare-and-life-sciences-jobs?sort=f)
SEO page (~41k jobs) — and sorted by freshness (`sort=f`, newest first).
Every card carries all the fields we need (title, company, salary, experience,
location, `createdDate` in **epoch ms**, `roleCategoryGid`, `jdURL`), so no
detail-page fetch is needed.

### Why a browser capture (not live HTTP)

The `/jobapi/v3/search` endpoint requires a per-request **signed `nkparam`
header** generated by the site's own JavaScript. Requests without it get
`HTTP 406 {"message":"recaptcha required"}`, and the whole domain sits behind
Akamai (which resets non-browser TLS fingerprints — plain `curl` is killed
mid-response). So, exactly like this repo's [`indeed/`](../indeed) scraper,
the JSON is **captured in a real browser** and this script consumes it offline.

### robots.txt

Checked and honored (master-spec §7). The `User-agent: *` group does **not**
disallow the healthcare listing or `/jobapi/`; only recruiter/admin paths are
blocked. naukri separately disallows automated AI crawlers (`claudebot`,
`gptbot`, `perplexitybot`, …) from `/`. We do **not** crawl as a bot — a human
drives the browser capture of the human-facing listing, and this script only
transforms the already-captured JSON.

## Capturing a fresh page set

In a browser on `https://www.naukri.com/healthcare-and-life-sciences-jobs?sort=f`,
install a fetch/XHR interceptor that accumulates `jobDetails` from every
`jobapi/v3/search` response, then page through the listing (click **Next**;
navigation is client-side so the interceptor survives). Dump the accumulated
array to `captures/<DD-MM-YYYY>.json`:

```js
// 1. interceptor — run once on the listing page
window.__jobStore = {};
const save = (u, t) => { if(!/jobapi\/v3\/search/.test(u)) return;
  try { JSON.parse(t).jobDetails?.forEach(j => j.jobId && (window.__jobStore[j.jobId]=j)); } catch(e){} };
const of = fetch; window.fetch = function(){ return of.apply(this,arguments)
  .then(r => { r.clone().text().then(t => save(r.url, t)); return r; }); };
// (also hook XMLHttpRequest.send for the pages naukri fetches over XHR)

// 2. page through, then export
JSON.stringify(Object.values(window.__jobStore));   // -> save to captures/<date>.json
```

`captures/08-08-2026.json` in this folder is a real 898-job capture spanning
2026-08-06 → 2026-08-08.

The loader also accepts a raw single API response (`{"jobDetails":[...]}`) or a
list of such responses, so any capture shape works.

## Usage

```bash
pip install -r requirements.txt          # shared venv at ../../.venv

# ingest the newest capture in captures/ (default)
python naukri_scraper.py

# or a specific capture, with a fixed run-date folder
python naukri_scraper.py --from-json captures/08-08-2026.json --run-date 08-08-2026

python naukri_scraper.py --limit 50 --verbose   # small test run
python test_filters.py                          # unit tests
```

### Options

| flag | meaning |
|------|---------|
| `--from-json FILE` | capture JSON to ingest (default: newest in `captures/`) |
| `--output PATH`    | rich cumulative CSV (default `naukri_jobs.csv`) |
| `--run-date DD-MM-YYYY` | `jobs_csv/<date>/naukri.csv` folder (default: today) |
| `--limit N`        | stop after N new jobs (test runs) |
| `--verbose`        | debug logging |

## Outputs

- **`naukri_jobs.csv`** — rich cumulative store, dedup key `job_id`, the source
  of truth for the incremental watermark.
- **`../../jobs_csv/<DD-MM-YYYY>/naukri_roles.csv`** — exactly the 22
  `CLUB_COLUMNS` imported from `_shared/classification.py`, including
  `category`, `sub_category` and `qualification`; the old
  `is_active`/`expires_at` columns are retired. naukri cards carry no
  structured qualification field, so `qualification` is
  `extract_qualification(description)` — never inferred.
- **`needs_review.csv`** — in-scope rows the classifier flagged (kept, never
  dropped — master-spec §2).
- **`out-of-scope.csv`** — rows the classifier dropped from the rich store
  during the one-off taxonomy migration (reversible archive).

## Quirks & conventions

- **Salary** (§3, capture-don't-filter): naukri salaries are INR **per annum**;
  `salaryDetail` holds the full integer range (e.g. `4500000`), and the card's
  placeholder (`"45-60 Lacs PA"`) is kept verbatim as `salary_raw`. Hidden or
  absent pay → `Not Disclosed`, numeric fields empty. The club CSV only
  represents INR/USD, so non-INR pay leaves the club salary columns empty.
- **Classification — the shared taxonomy only.** Every card runs through
  `_shared/classification.classify_job` with three signals: `title`,
  `tagsAndSkills` as `skills`, and the HTML-stripped `jobDescription`. The
  scraper defines no category regexes or enums of its own.
  - `in_scope == False` → the card is **dropped**, counted as
    `excluded_out_of_scope` and printed in the run summary. Even the
    role-family searches return plenty of bedside and non-healthcare noise:
    the scope is **Non Clinical + Public Health** roles only.
  - In-scope cards get `category` = `Non Clinical` | `Public Health` and
    `sub_category` (one of the 20 sub-categories), plus the rich-CSV trace
    columns `role_family`, `sub_category_basis`, `all_families`,
    `family_scores`, `family_confidence`, `matched_in`.
  - `roleCategoryGid` is retained in the rich CSV as raw source data only —
    it never decides the category.
- **Company**: for consultant postings that don't hide the client, the client
  name is captured in `hiring_for`; `company` stays the posting/recruiter name.
- **Country**: naukri is India-first (`India / IN / +91` default); overseas
  postings whose location is a bare country name (e.g. "Saudi Arabia") are
  mapped via `COUNTRY_META`.
- **Time window** (§4): first run keeps the last `INITIAL_WINDOW_DAYS = 7`;
  later runs keep jobs newer than the stored watermark minus
  `WATERMARK_GRACE_DAYS = 2`. naukri posts hundreds of healthcare jobs/day, so
  the window stays deliberately tight.
- **Idempotency** (§5): re-running against the same capture adds 0 rows.

## Re-scoped to the eleven role families (2026-08-24)

This is the role-scoped fork of `../naukri/`. The original is untouched and
still scrapes the broad Healthcare & Life Sciences functional area.

**Scope.** Only these are kept, via `../_shared/role_families.py`:

    Public Health · Clinical Data Management · Clinical Research ·
    Medical Writer · TMF · Medical Coding · Pharmacovigilance ·
    Regulatory Affairs · Medical Reviewer · MSL · HEOR

**Matching uses three fields, not just the title** — `title`,
`tagsAndSkills` and `jobDescription`, weighted 5 / 2 / 1. Naukri is the
source that makes this matter most: many Indian CRO and KPO listings carry a
generic title ("Senior Executive", "Wanted Life Science Graduates") and name
the domain only in the skill tags.

Measured on the two captures in `captures/` (2,171 cards): **402 in scope
(19%)**, of which **49 (12%) had no title match at all** and were found
purely through tags or description.

### Capture recipe — search per family, not the healthcare listing

The API still needs a browser-signed `nkparam`, so capture is unchanged in
mechanics — but drive it from the **role-family searches** instead of the
Healthcare & Life Sciences functional area. Page through each of these with
`sort=f` (freshest first) while the interceptor accumulates `jobDetails`:

    clinical research · clinical research associate · clinical trials
    clinical data management · pharmacovigilance · drug safety
    regulatory affairs · medical writing · medical coding
    medical science liaison · medical monitor · health economics
    market access · trial master file · public health · epidemiology

Dump the accumulated cards to `captures/<DD-MM-YYYY>.json` exactly as before;
this scraper consumes them offline. Searching the families directly is master
spec §1 (filter at the source) and avoids paging 41k healthcare jobs to find
the ~19% that are in scope.

**Time window**: first run keeps the last 2 days
(`INITIAL_WINDOW_DAYS = 2`); later runs use the watermark. Note the captures
in this folder are from 2026-08-08/10, so a run today discards them all as
older than the cutoff — take a fresh capture.
